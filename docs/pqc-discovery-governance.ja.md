# PQC discovery論文：棚卸しを次の判断につなげる

[English](pqc-discovery-governance.md) | [日本語](pqc-discovery-governance.ja.md)

## 人・PMO向けの短い概要

暗号を見つけた後に「誰が責任を持ち、何を根拠に、いつ次の判断をするか」を残すことが、この論文の実用的な示唆です。本ラボでは、まず既存の運用確認票を使った手作業の演習に活用できます。証拠不足の調査と移行判断を分け、別の人が根拠をたどれるかを確認します。以下は検証案であり、論文と同じ実験を実施した記録ではありません。

## 実験条件・主張・限界

第3～5節では、静的調査・稼働時の観測・依存関係の把握から、Quantum Exposure Register（QER：量子リスクの管理台帳）を作り、責任者・証拠の確かさ・移行の前提を補います。対象は物流・デジタルID・金融・決済に関わる欧州の重要サービス提供者1組織です。

第8節の著者報告値は、14か月、148環境、24,350接続先、87,200証明書、RSA約68%・ECC約32%、管理担当が不明な暗号資産約40%、時間上のリスクがある重要サービス12件（全ポートフォリオの3%未満）です。接続先・証明書・資産・サービスは異なる単位なので、これらを検出率や網羅率として扱えません。

主張は、一度きりの一覧から、証拠と責任と供給者の制約を継続的に更新する管理へ進めることです。第7節は、単一組織・匿名データ・ツール非依存の記述・量子脅威時期の不確実性を限界として挙げます。生データ、ツール版、測定条件、誤検出率の比較等は再現に十分ではありません。静的・動的調査を併用した効果や工数削減を本ラボで実証済みとは言えません。

## 数式を採用する前のレビュー

式(1)、PDF 6ページは、必要な機密保護期間と移行所要時間の合計が脅威までの想定期間を超えるかを見ます。9ページの8年は計画用シナリオで、量子コンピューターの到来予測ではありません。保存年数だけで機密保護期間は決まりません。署名・長寿命機器では完全性や認証の有効期間も別に確認します。

式(2)、12ページの優先度は、重要度×0.4＋時間上のリスク×0.4＋証拠不足の加点×0.2です。重要度と時間上のリスクは1～3、証拠不足はHigh=0・Medium=1・Low=2。弱い証拠で調査優先度が上がっても、リスクが確定したことにはなりません。重み・Wave区分は組織固有です。本ラボの[0～100の変更能力スコア](scoring.md)、P1～P3、論文の1～5の変更能力・Wave 1～4は別の尺度です。

以下は原文を照合した際のレビュー観察で、論文の修正や本ラボの実測結果ではありません。

- 表1、11ページのQER-010は8+3>8でもBorderline。QER-006は7+1=8でNo。Borderlineの数値定義がなく、等号・欠損値の規則も採用前に明示が必要です。
- QER-007のC/I/AはHigh/Medium/High、時間上のリスクYes、証拠Lowです。Highを重要度の代表値とする場合、式(2)では2.8、表2ならWave 1ですが、表1はWave 2です。集約規則は未定義で、管理判断で変更した可能性もあるものの、個別の変更理由は示されていません。
- C/I/Aの3値を1値へまとめる一般規則が不明です。節番号・参照番号にも不整合があるため、PDFページ・式・表番号で根拠を追います。

## 現在のinventoryとの対応

| 論文の要素 | 現在使えるもの | 補う点 |
|---|---|---|
| 調査根拠 | 相対パス・行・方式・検出信頼度 | 検出の確かさと実稼働の証明を分ける |
| 稼働・依存関係 | 別のTLS観測、`verification_source` | TLSとディレクトリの自動統合、全環境観測、供給者依存グラフは未実装 |
| 責任・用途 | `owner`、`purpose`、`runtime_state` | 業務の説明責任者と技術担当を補足票で区別 |
| 時間上のリスク | `data_retention_years`、`exposure` | 機密期間の根拠・移行期間・脅威想定を手動で補う。現行`exposure`の公開範囲等と式(1)の結果を混ぜない |
| 証拠・次の対応 | `verification_source`、`next_action`、静的/申告/不明の区別 | 出典・観測日・不確実性・判断を別々に残す |
| 継続更新 | `compare`の根拠差分 | 根拠の消失を配備完了にせず、判断日と理由を記録 |

## 最小の次の検証案（未実施・オフライン）

[既存の記入例](../samples/mini-service-review-example.csv)と[模擬システムの正解表](../samples/mini-service-ground-truth.json)を読むだけで始めます。新しいscan・暗号変更・供給者への連絡は不要です。署名・通信・保存データ・廃止コードを選び、非公開の補足票に資産ID、対応する検出根拠、出典・日付・範囲、観測/申告/不明、業務責任・技術担当、C/I/Aの理由、機密性と完全性の必要期間、移行見積りの幅、供給者制約、脅威シナリオ、独立した時間判定、次の証拠収集、次の判断日を記します。現行CSVの列追加を実装した意味ではありません。

1. 見落とされた通信・保存データも含め、複数の検出と一つのサービスの対応を残す。12年保存は演習上の申告であり、機密期間の実測やAES自体のPQC置換理由ではない。公開鍵の鍵ラップや通信依存は別に確認する。
2. 架空の前提を明示し、合計が脅威想定より短い・等しい・長い例と欠損例を手計算する。欠損はUnknown、Borderlineは定義するまで割り当てない。シナリオを変えた感度を確認する。
3. 証拠不足は移行順位の断定より調査の対応へつなぐ。廃止SHA-1の実使用確認と古典的な衝突リスクを、PQCと分ける。
4. 別のレビュー担当が根拠を追えるか確認する。全判断に出典がある、手動追加・不明が消えない、静的検出を実稼働の証明にしない、順位変更には理由がある、を合格条件とする。満たせなければ実装検討前に票を直す。

PMOは、この演習で定義した母数とともに、責任未確定・証拠不足・供給者待ちを確認できます。効果と回収できる工数は今後の測定対象です。今回の更新は文書のみで、QER機能や数式の自動計算は未実装です。
