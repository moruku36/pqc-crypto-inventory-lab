# 用語の早見表

[READMEへ戻る](../README.md)

このプロジェクトを読むための短い説明です。詳しい仕組みは[学習ノート](security-specialist-notes.md)にあります。

| 言葉 | このプロジェクトでは |
|---|---|
| 暗号の棚卸し / Crypto Inventory | どの場所でどの暗号方式が使われていそうか、一覧にすること |
| PQC | 量子計算による攻撃も考慮した公開鍵暗号方式。Post-Quantum Cryptographyの略 |
| Crypto Agility | 暗号方式を変えるとき、安全性やサービスの動作を保って移行できる能力 |
| アルゴリズム | 計算や処理の手順。ここではRSA、AESなどの方式 |
| 公開鍵 / 秘密鍵 | 対になる鍵。公開鍵は共有できるが、秘密鍵は本人側で保護する |
| 共通鍵 | 通信相手などと共有して秘密にする鍵 |
| 鍵交換・鍵確立 | 通信で使う共有秘密を決める仕組み |
| 電子署名 | 秘密鍵で作り、公開鍵で確かめる情報。改ざんや署名者の確認に使う |
| ハッシュ | データから一定の長さの値を計算する処理。暗号化のように復号するものではない |
| TLS | HTTPSなどで利用される、安全な通信のための仕組み |
| ハンドシェイク | 通信を始めるときに、方式や鍵に関する情報を取り決めるやり取り |
| 暗号スイート / cipher suite | 通信で使う暗号処理の組合せの名前。含まれる情報はTLSの版で異なる |
| 証明書 / X.509 | 主体の公開鍵などを、発行者の署名とともに記録したもの／その形式 |
| PKI / CA | 証明書を発行・検証・管理する仕組み／証明書を発行する認証局 |
| CRL / OCSP | 証明書が失効しているかを確認するための仕組み |
| PEM / DER | 証明書や鍵を保存・交換する表現形式。どちらも内容が公開情報とは限らない |
| KEM | 共有秘密を確立する仕組みの一種。本文の暗号化や署名とは役割が異なる |
| ML-KEM / ML-DSA / SLH-DSA | このプロジェクトで紹介するPQC候補。前者は鍵確立、後二者は署名 |
| CLI / ターミナル | 文字のコマンドで操作する仕組み／コマンドを入力する画面 |
| ディレクトリ / パス | フォルダー／ファイルやフォルダーの場所を表す文字列 |
| JSON | 項目名と値を組にしてデータを表す形式。出力例の`"score": 25`など |
| Markdown | `#`で見出しを書くなど、テキストで文書の構造を表す形式。`.md`のファイル |
| ライブラリ / API | 再利用できるプログラム部品／その機能を呼び出すための入口 |
| 静的解析 / AST | プログラムを実行せず内容を調べること／構文の構造を表す木。このツールではPythonの呼出しを調べる |
| manifest | 補助情報をまとめた設定ファイル。ここでは採点の申告用`.pqc-agility.json` |
| CI / GitHub Actions | コードの変更後に自動で検査する仕組み／GitHubでその検査を動かす機能 |
| pytest / Ruff / mypy | 動作のテスト／コードの書き方の検査／値の種類の使い方の検査に使う開発ツール |
| commit / push | 変更をGitの履歴に記録すること／その履歴をGitHub側に送ること |
| Phase | 開発を分けた段階。利用者が順に実装し直す必要はない |
